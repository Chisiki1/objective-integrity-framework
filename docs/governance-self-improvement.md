# Governance and Self-Improvement

Self-improvement means a real result changes a later matching action and produces an observable effect. The framework keeps that loop actionable while preserving the current task's primary objective.

## Learning Records

Use two source layers and one retrieval projection when the cost is justified:

- A project master preserves exact project evidence, raw observations, failed alternatives, and local return steps.
- A global master receives sanitized reusable knowledge, applicability, proof ceiling, and recurrence constraints.
- A source-hash-bound index makes current controls and relevant history retrievable without becoming a third semantic authority.

The records are support infrastructure. The current source, artifact, runtime, and external state remain authoritative for their own claims.

Keep current guidance small and replace superseded current advice, with complete source-linked history retained behind it. Organize touched knowledge families at meaningful results or recurrence instead of appending the same rule again. [Knowledge Stewardship](knowledge-stewardship.md) explains backing-first organization and archive-aware retrieval.

## Actionable Learning Queue

The learning queue owns the path from discovery to later use:

```text
discovered -> prepared -> evaluated -> active-bounded -> measured
           -> revise | narrow | merge | supersede | retire
```

Each candidate binds its source objective, causal family, owner, artifact, next-use trigger, expected effect, rollback, evidence, and current disposition. Immutable queue events preserve why the state changed. `due` retrieves candidates for an exact objective, family, and trigger; it does not authorize their use.

Missing measurements remain unavailable. They are not converted to zero, success, or failure. Deferral requires a reason and a concrete return trigger.

Once standing authority, preserved conditions, representative normal-path evidence, independent challenge, bounded adoption and rollback are satisfied, implement and carry the candidate to its actual next consumer without waiting for another user prompt. A pending condition amendment holds only that amendment's dependent action, not ordinary improvements already within authority. Correct queue metadata without pretending that a new observation or lifecycle transition happened.

## Skill Book Feedback

When reusable guidance is selected, keep these states distinct:

1. source and action facts compiled;
2. guidance selected or rejected;
3. selected bytes delivered and revalidated;
4. exact action executed or held;
5. action result observed;
6. independent consumer effect observed;
7. lifecycle disposition updated.

An effect record distinguishes planned and actual objective delta, planned and actual evidence delta, consumer result, side effects, rollback, cost, rework, counterevidence, and proof ceiling.

Project records retain exact effects and failed alternatives. Global records receive only sanitized reusable families, aggregate effect, applicability, invalidation trigger, and proof ceiling. This keeps shared guidance useful without copying task-private evidence.

## Condition Stewardship

Conditions have different authorities:

- Higher-priority platform or tool constraints remain outside project governance.
- User-authored conditions change meaning only through an exact later user source that identifies the amendment's scope.
- Delegated implementation methods may be improved autonomously when the source meaning, normal path, evidence, recovery, and rollback remain intact.
- Unknown authority is investigated only for the dependent decision; it does not stop unrelated work.

When a user-approved amendment is needed, preserve the old and proposed text, exact source, affected condition set, meaning and scope delta, dependent conditions, expected benefit and cost, lost guarantees, independent challenge, rollback, effective period, and later effect. Approval-shaped files and structural matching never create authority.

An approved amendment supersedes the old condition only within its exact scope. Every unaffected condition remains active, and the old source and rollback lineage remain available.

## Dynamic Allocation

Choose model capability, reasoning depth, tools, delegation, and review independently from the work's actual shape. Record required capability, eligible configurations, requested and accepted configuration, observed effective metadata when available, expected total cost, and the concrete failure a weaker configuration would risk.

Risk can strengthen evidence and independent review without automatically selecting the most expensive execution configuration. A domain label such as security, financial, or production does not determine the model by itself.

## Improving the Framework

Before adding a new permanent mechanism, show:

- The existing invariant that failed or could not express the case.
- The reusable failure family.
- Expected outcome or cost improvement.
- Independent challenge or representative replay.
- No-drop preservation of older obligations.
- Rollback conditions.

Prefer changing, merging, narrowing, or retiring an existing method when that closes the gap more cheaply. A new rule, skill, index, queue entry, or validator is not itself an improvement outcome.

## Effect Review

At a stalled integration, recurring failure or support-heavy result, compare changing the work unit, representation, entrypoint or ownership with a smaller correction and unchanged reuse. Consolidating or removing a mechanism can be the strongest improvement. Select by source outcome and total delivery cost, not novelty, rule count or a requirement to invent a breakthrough every turn. Carry the selected change into the next real dispatch or action; see the [convergence contract](../runtime/skills/master-guided-skill-lifecycle/references/convergence.md).

When a capability change or uncertain premise can alter that decision, gather focused external evidence and a credible counterexample. Prefer current primary sources; distinguish API availability from actual host support, configuration, delivery and observed use. [External calibration](../runtime/skills/master-guided-skill-lifecycle/references/external-calibration.md) supplies the route and source seeds. Research serves a decision, not a browsing quota.

At the next eligible consumer, compare planned and actual objective progress, mandatory quality, evidence, rework, false holds, misses, elapsed and tool cost, rollback, and final consumer result. Preserve unavailable and not-applicable values as typed states. Continue, revise, narrow, merge, or retire the method from that observed episode.
