# Learning during work

Use the actual task result as the starting point. A missing reference, recurring
mistake, successful reusable procedure or expensive handoff can justify learning;
none automatically proves a cause or warrants creating another Skill.

1. Preserve the result, first fault, relevant inputs and uncertain effects. An
   empty display is not success. Find the earliest meaningful failing boundary;
   keep unrelated useful work moving.
2. Compare unchanged reuse, a small correction, and a structural alternative when
   useful. A different work unit, typed caller, shared representation or removed
   mechanism can outperform another reminder. Compare total delivery cost and
   the user's outcome, not novelty or document length.
3. Put the correction where the next action actually consumes it: selection,
   caller, instructions, script, applicability or environment. Use existing tools
   when sufficient. Create or revise a Skill only for a reusable procedure with a
   real next consumer; include every necessary script, reference and example.
4. Keep a candidate inactive until its proportional normal/negative checks,
   independent challenge, authority, preservation and recovery needs close.
   Then use the eligible improvement in the current task without waiting for a
   separate request. A user-owned condition still needs the user's exact approval
   to change; pending approval holds only the dependent amendment.
5. Observe the next matching action. Distinguish a delivered file, actual use,
   observed effect and general benefit. Record available rework, false holds and
   total cost; unavailable measurements are not zero. Retain, revise, merge,
   narrow or retire the method accordingly.

At resume, compaction or a relevant method change, each continuing actor reads its
own affected instructions before the next safe dependent action. Reuse unchanged
personal reading; a parent's receipt or hook context does not prove a child's
reading or application. Preserve in-flight old versions and unknown effects.

Keep one current disposition per affected knowledge family. Review every current
location touched by a change, replace stale guidance and keep exact source-linked
history retrievable. Do not stack another current status beneath the old one or
delete unresolved obligations while shortening a record.

## Optional executable route

The complete OIF distribution provides `tools/oif.py operation` for native result
capture, `work` for result-derived next requests, `candidate` for complete Skill
packages, `index` for bounded history retrieval and `reconcile` for owner-authored
whole-current reconciliation. Follow each bundled command's versioned help and
contract. They require an explicitly chosen writable location and Python; they
are not dependencies of the instruction-only plugin.

Neither these helpers nor hooks retrain model weights, supply new permissions or
ensure automatic improvement. Their value is a better real next action with
preserved source and recovery, not invocation or file counts.
