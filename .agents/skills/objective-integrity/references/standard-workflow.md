# Standard Workflow

Use the standard profile for ordinary material work.

## Start From the Outcome

Classify every source clause before planning. Keep the primary objective, independent deliverables, acceptance criteria, authority, methods, preferences, and prohibited substitutes distinct. If two faithful interpretations would materially change the deliverable, authority, or tradeoff, ask for that decision. Otherwise use the narrowest interpretation that satisfies the source.

For each material action, record:

- the exact source claim it advances;
- the causal contribution and omission consequence;
- the expected objective and evidence delta;
- the evidence route and proof ceiling;
- the current blocker return step, if any;
- the next eligible primary-objective work.

Retire or defer work that has no source-bound omission consequence. Tests, reviews, ledgers, and tools remain means unless the source made them deliverables.

## Working Records

Keep one completion scope mapping every requirement to its implementation items, required connections and acceptance checks. In BUILD, implement that whole scope; small construction feedback only answers a next-build question. In SWEEP, freeze the candidate and collect all safe independent stage findings. In REPAIR, preserve the first findings and repair their shared causes together. In ACCEPT, return to the original consumer outcome. A child job's completion is not the whole scope's completion. Never relabel an external action as build feedback to bypass its prerequisites.

These are owner decisions, not a mandatory collection of new tools. A minimal Skill installation can keep them in existing project records. Complete runtime mode adds executable phase and handoff checks without replacing semantic judgment.

Create or update only the records the work needs:

- Objective contract.
- Open deliverable ledger.
- Evidence map.
- Scenario and interaction ledger for material risks.
- Audit receipt when independent review can change a decision.
- Action outcome and effect record when a result can be partial, uncertain, or reusable.

Before a candidate-bearing change, freeze the supported normal path, intended semantic delta, preservation contracts, blind scenario families, reachable interactions, impact cone, potential new failures, and consumer oracles. Keep tests and audits subordinate to the requested outcome.

If a verifier fails, separate product failure, escaped product failure, and verification-model failure before changing either product or test. Preserve skipped dependent paths as not observed instead of passing them.

One primary owner performs authorized work and maintains the objective state. Independent review remains read-only toward its target and derives its challenge from the source and fixed evidence, not the owner's conclusion.

Finish when the normal consumer outcome and mandatory conditions are supported within their evidence routes. A blocked state names the minimum unblock condition and exact return step; it is not completion and not a replacement objective.
