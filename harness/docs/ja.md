# OIF Desktop ガイド

バージョン **0.4.0** · [English](guide.md)

## 起動

1. [リリース](https://github.com/Chisiki1/objective-integrity-framework/releases/tag/v0.4.0)から **OIF-Desktop-0.4.0-windows-x64.zip** を取得します。
2. ZIP全体を書き込み可能なフォルダーに展開し、**OIF.exe** を開きます。Pythonは同梱されています。EXEだけを別の場所に移動しないでください。
3. 設定で接続先・モデルを指定し、必要な場合はAPIキーを入力して作業を始めます。OpenRouterにはブラウザーでのサインイン経路もあります。OAuthが全プロバイダーに対応するわけではありません。

Windows 10/11 x64と[WebView2 Evergreen Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)が必要です。このアプリはコード署名されていないため、Windowsが実行前に確認を表示する場合があります。同じリリースのチェックサムでZIPを確認してください。

最初は「answer.txtに改行なしでhelloと保存し、読み戻して確認してください」と依頼してみてください。

## 作業の見方

一つのチャットで追加指示を出すと、その指示の進捗と結果を確認できます。上部に受領・反映状態を表示し、前の進捗は畳まれます。現在の作業も手動で畳めます。

既定の「重要な進捗だけ」は節目・判断・失敗・結果を表示します。「すべての進捗」はモデルと操作の詳細も含みます。最新を追っている時は更新に追従し、過去へ戻っている時は読んでいる位置を保ちます。全工程の一覧は新しい順です。項目を開くと詳しい説明と原記録が見られ、解説も要求できます。

成果物は最新の版から確認できます。テキスト・Markdown・画像・PDFはプレビューでき、ダウンロードは別操作です。長い記録はページごとに取得します。作業の詳細から未完了事項、改善案、スキルを確認できます。タスクの右クリックで名前・ピン留め・アーカイブ・整理・ローカルリンクを操作できます。リンクはこのインストールで開くためのもので、公開共有ではありません。

## 指示の送信

新しい作業と追加指示はEnterで送信し、Shift+Enterで改行します。「接続設定 → 送信キー」で「Ctrl/Cmd+Enterで送信」を選ぶと、Enterは改行になります。変更はすぐに反映され、この端末に保存されます。日本語などの変換確定では送信しません。

## モデル・権限・長期作業

### このPCのローカルモデルを使う

Ollama、LM Studio、llama.cppなどのOpenAI互換サーバーに接続できます。モデルサーバーを起動し、接続設定で「互換API」を選びます。Ollamaの接続先は `http://127.0.0.1:11434/v1`、モデル欄にはインストール済みの正確なモデル名を指定します。認証のないローカルサーバーではAPIキーは空欄で使えます。認証を有効にしたサーバーには、そのサーバーのキーを指定してください。

ローカル接続では、操作内容を含むJSON形式をサーバーに指定します。説明だけ返して操作指示が抜ける問題を減らし、返答は実行前にも検証します。対応していないサーバーでは「モデル接続の詳細 → 応答の形式」で「標準JSON」を選べます。方式や接続先を黙って変更して再送することはありません。クラウド接続の初期値は従来のJSON形式です。[Ollamaの構造化出力](https://docs.ollama.com/capabilities/structured-outputs)

先に現在のクラウド接続に名前を付けて保存すると、後から戻せます。ローカル接続へ変更する時にキーを入力しなければ、前の接続のキーは引き継ぎません。HTTPを許可するのは `127.0.0.1`、`localhost`、`[::1]` のみです。Web情報収集の通信設定は別です。モデルをローカルにしても、依頼したWeb調査までオフラインにはなりません。

文脈・出力の上限は、モデルサーバーの実際の設定に合わせます。OllamaではOIFの入力欄を変えるだけでサーバー側の文脈は増えません。必要な場合は、既存モデルを元に `FROM モデル名` と `PARAMETER num_ctx 65536` を書いたModelfileを作り、`ollama create oif-local -f Modelfile` で専用のモデル名を追加して使います。[Ollamaの設定手順](https://docs.ollama.com/api/openai-compatibility#setting-the-local-context-size)

### 権限と文脈の管理

モデル名、接続先、役割やプロファイルを設定できます。モデルに合うコンテキストと出力上限を指定してください。長期作業では作業用の文脈を圧縮し、原記録は必要な範囲で取得します。圧縮した要約を原指示や証拠より上位に扱いません。

入力欄で権限を選びます。作業フォルダーの権限では通常のファイル操作をタスクの作業領域に制限します。確認するモード、読み取り専用、確認付きのフルアクセスもあります。フルアクセスは領域外のネイティブ操作も可能になるため、意図した作業に使用してください。権限の変更は次の操作から適用されます。

APIキーは現在のWindowsユーザー向けに保護されます。タスクに必要な情報は設定したモデルプロバイダーへ送信されます。調査では設定した調査経路へ公開の検索語を送ります。指示や学習メモに秘密情報を入れないでください。

## 今回の指示と実作業

完了済みの依頼と結果は履歴に残し、新しい回答では今回の指示と未完了の作業を扱います。追加・訂正した指示を完了条件に結び付け、目的文だけ更新して反映済みにすることを防ぎます。ファイル作成・プログラム実行・ブラウザー観測では、実際の操作結果を確認してから完了を判断します。

作業フォルダー内のPython実行にはDockerを使います。フルアクセスを選んだ場合は、このPCのPythonやコマンドをネイティブに実行します。Dockerがなくても、ファイル作成、公開Webの取得、ブラウザー観測は利用できます。

## Web調査

公開HTTPSページを直接読む場合は「公開URL」を選びます。キーワード検索には、設定画面でBraveまたはTavilyと対応するAPIキーを指定します。ページの本文に加えて、実在するリンク、フォーム項目、スクリプトURL、ページ情報を取得します。モデルが選んだリンク先も同じ公開ネットワークの検査を通します。リンクの取得だけでスクリプトを実行したり、フォームを送信したりしません。

大きなページは個別に抜粋し、サイトマップだけで他の取得結果が埋もれないようにします。保存済み本文・構造情報・元のHTMLやJavaScriptは、`history_read`で検索・部分読み取りできます。保存済み応答の読み取りでは再通信しません。確定したHTTPエラーがあっても取得済みのページを保持し、同時に依頼された他のURLは取得できます。作用が不明な場合や秘密情報の検査では、従来の復旧上の制約を維持します。

大きなJavaScriptでは、エージェントが<code>web_fetch(max_bytes=8000000)</code>で1応答あたり最大8MBまで指定できます。保存済みの既定設定は変更しません。取得量の上限に達した場合は、途中までの内容と明示して検索できるように保存し、独立した他のページの取得を続けます。<code>history_read(view=web_response, query=["fetch(", "sendBeacon", "localStorage"])</code>で複数の文字列をまとめて調べられます。途中までの内容に見つからなくても、ファイル全体に存在しないとは判断しません。以前の容量上限で保留になった操作も、保存済みのバイト列を検証して復旧し、同じ通信は繰り返しません。

動的なページには`browser_inspect`を使います。新しい隔離ブラウザーでJavaScriptを実行し、表示内容、コンソールのエラー、通信の試行、Cookie・localStorage・sessionStorageを観測します。作業フォルダー内で作成したHTMLも実行して確認できます。Windowsではインストール済みのEdgeまたはChromeを使います。他の環境ではOIFの依存関係を導入した後に`python -m playwright install chromium`でChromiumを用意します。ブラウザー観測にDockerは不要です。

観測は未ログインの新しい環境で、ページを開く範囲です。公開HTTPSのGET・HEAD通信は、取得先アドレスを検証して固定する既存の通信経路を通します。POST、WebSocket、Service Worker、画像などのメディア本体、ダウンロードは今回の対象外で、遮断した試行は結果に表示します。最初のURLの転送先は取得前に検証し、最後のURLをブラウザーで開きます。転送途中で設定されたCookieは引き継がず、スクリプトなどの追加取得で発生する転送は記録して遮断します。作業フォルダーのHTMLから外部への通信も遮断します。普段使っているブラウザーのプロファイル・ログイン状態は使用せず、フォーム操作もしません。時間・件数・取得量の上限と途中までの観測を明示します。静的ソースとブラウザー実行の証拠を区別し、脆弱性が存在しないことやログイン後の全動作を確認したとは扱いません。

## 自己改善と共有

実際の経験から、根拠・使う条件・手順・限界・次に使う場面を備えた教訓を保存します。一般化できる手順は他の新しいチャットでも選択候補になります。タスク固有の原資料や権限を全体へ移すものではありません。

実際の利用と結果を記録し、必要なら改良・統合・退役します。退役したものは通常の選択から外れ、履歴は残ります。保存数は性能の点数ではありません。単純なファイル作成で新しい教訓がゼロでも正常です。

完全作業方針の目的・必須成果・権限・最初の失敗・復旧・学習を、実用的な実行頻度に落とし込んでいます。Web調査は依頼された調査や最新・不確かな外部情報で行い、毎回の単純なローカル操作には追加しません。任意の学習を理由に完成済みの成果物をいつまでも保留にしません。公開された方針と適用方法は `policy/complete-policy-v3.json` と `policy/practical-runtime-v1.json` で確認できます。

本体の改善は、公開可能な設定・許可されたソースの確認から、変更案、隔離検証、審査、適用、次の実利用、必要時の復旧へ進みます。明示されたユーザー条件を勝手に変更しません。隔離シェルと本体コードの検証には、Linuxコンテナーを動かせるDocker Desktopが必要です。通常のファイル作業・UI・プレビューには不要です。テストの成功だけで無制限の成長を証明するものではありません。

## 停止と復旧

新しい作業を送信できない時は、サービスの接続切れか入力の問題かを通知に表示します。「接続を復旧」は入力・添付を残したまま必要に応じてサービスに接続し直し、元の送信IDで受領記録を確認します。この操作では再送しません。受領記録がなければ「作業を開始」で送信できます。期限切れの接続情報は自動で更新します。

複数チャットを同時に進められます。停止は選択したタスクに作用し、記録は残ります。再開は保存された境界から行います。作用が不明な操作は再実行前に確認してください。チャットの表示を開き直すために他のチャットを再起動する必要はありません。

ウィンドウを閉じてもサービスと進行中の作業は継続します。サービス自体を止める時は、作業を完了または停止し、アプリの `scripts/Stop-Harness.ps1` を実行します。所有しているプロセスを検証して正常終了を要求します。終了が確認できない状態でデータベースを置き換えないでください。

## バックアップ・更新・戻す方法

### 画面から更新する

画面上部の「更新」を開きます。起動時に公式GitHubのリリースを確認し、結果を6時間保持します。「更新を確認」で取り直せます。β版ではβ版と正式版、正式版では正式版を案内します。取得できない時も通常の作業は続けられます。

「更新して再起動」を選ぶと、選択したWindows版をダウンロード・照合して適用します。更新は任意で、実行中の作業がある間は適用しません。同じ場所でアプリを開き直すため、ピン留め、`.runtime` のチャット・キー・学習、利用者のファイルを引き継ぎます。変更するアプリのファイルは `.runtime/product-updates` にバックアップします。公式リリースの照合値と配布内の全ファイル一覧を確認します。公式リポジトリから取得したファイルの照合であり、別途の発行者署名ではありません。

アプリの管理対象ファイルにローカルの変更があれば、上書きせず手動での統合を案内します。置き換えに失敗した場合は元のファイルへ戻してから開き直します。途中で更新処理が異常終了した場合も、次の通常起動で保存した元のファイルを復旧します。タスクの記録を巻き戻したり、タスクを自動で再実行したりしません。旧版と当時のデータをまとめて戻す場合は、フォルダー全体のバックアップを使用します。

本体のファイルが新しくなってもサービスに旧版が残っている場合は、この画面の「サービスを再起動」を選びます。作業が終わってから記録を保持して切り替え、画面を再接続します。デスクトップを開き直した時も、待機中の古いサービスは切り替わります。保留中のチャットは再接続後に「再開」できます。「表示を更新」は画面だけを更新します。

### 手動更新と全体のバックアップ

更新・再起動の前に、各チャットと新規作成欄の未送信の文や添付を送信するか、不要な入力を消してください。下書きや送信中の操作がある間はウィンドウを閉じずに待ちます。

1. 作業を完了または停止し、OIFのウィンドウを閉じます。`scripts/Stop-Harness.ps1` を実行し、終了を確認します。
2. アプリのフォルダー全体をバックアップします。`.runtime` にタスク、成果物、設定、保護されたキー、学習、復旧記録が入っています。同じWindowsユーザーで使用してください。
3. 新しいZIPとそのチェックサムを取得し、別の場所に展開します。まだ起動しません。
4. 旧フォルダーを別名で保持し、新しいフォルダーを**元と同じ絶対パス**に配置します。起動する前に旧版の `.runtime` をコピーします。稼働中のDBや二つのDBを混ぜないでください。
5. OIF.exeを開き、タスク一覧と設定を確認します。版や方針の照合が表示されたら内容を確認してから再開します。通常作業を確認するまでバックアップを保持します。

戻す時は現在の版を停止し、新しい作業も別途保存したうえで、バックアップ全体を元と同じパスへ戻します。バックアップ時点への復元なので、それ以降の作業は別に残してください。デスクトップの表示設定はインストール先に対応するユーザーのローカルOIFプロファイルに保存されます。非公開の開発環境や別のFramework・プラグインを自動移行する機能ではありません。

## 対応範囲と検証

Windows x64とPracticalEngineが対象です。自動テストは再現可能な仮のプロバイダーや作業領域を使います。紹介画面はサンプルと明示しています。実プロバイダー、OSの確認画面、外部サービスの変化による動作は環境ごとに確認が必要です。不具合報告には版、対象操作、秘密情報を除いた最初のエラーと途中成果を添えてください。
