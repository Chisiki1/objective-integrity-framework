# Reconcile the current view, retain the complete history

Use only when an actual current update, conflict or retrieval cost makes organization worthwhile. The owner remains the semantic writer. This is the existing two-master update, not a third editable knowledge ledger, a new permission, or a task-end clean-up phase.

## Current truth and update scope

Identify every current place affected by the changed fact: current event, CURRENT CONTROL, knowledge/Skill index, related family and relevant cross-master link. Replace their disposition together. A latest-event replacement does not reconcile an old current header elsewhere. Unrelated owners' current meaning stays unchanged. Route volatile task state, authority, next action and open outcomes to the existing chat objective/work state; route installed Skill versions to the actual registry. Resolve/read those sources at use. An unavailable pointer is not evidence of completion, permission or an empty backlog.

Keep stable reusable knowledge in the master, raw episodes in Project history, sanitized cross-links in Global. A historical or suspended work unit needs an explicit frontier and retrieval link until its source owner resolves or supersedes it; do not mark it completed just because a newer task exists. Current-path references and immutable evidence snapshots serve different purposes. Do not freeze a live path hash into an eternal current-state claim.

## Exact proposal and publication

Use `master_reconcile.inventory(master)` to partition the exact source into byte-bound sections. Author a `master-reconciliation-plan-v1` object with `owner`, exact `master_ref` and `replacement_ref` (`path`, `sha256`), absolute `history_path`, exact `source_refs`, and `groups`. Each group contains `section_ids`, `disposition` (`keep`, `replace`, `archive`), source-bound `reason`, `target_heading` or null, and `evidence_refs`. Groups must cover every source section exactly once. Keep retains the exact section occurrence, ancestry and current/history role, not just bytes found somewhere in the replacement. Identical siblings remain distinct by occurrence; an ambiguous changed ordering needs explicit reconciliation. Intentional moves use replace/archive with source evidence and a unique target heading; movement itself is not forbidden. Changed current controls require an explicit current replacement or historical-frontier disposition. Reconcile children of changed headings explicitly. The replacement body has no history markers: the proposal adds one link to the complete prior cut, which retains all earlier transitive history.

`master_reconcile.propose(plan)` / `propose --input <plan.json>` reads and validates but does not write. Keep its generated proposal outside active sources. Independently review semantic faithfulness, normal retrieval, all unresolved authority/obligations, legacy callers and exact destinations. The established scoped publisher stages/readbacks the complete preimage FIRST, then CAS-installs the reviewed replacement. A concurrent change holds only that publication; do not regenerate and overwrite it silently. Retain unknown/partial effects and use the existing rollback route. After publication, call `master_reconcile.readback(proposal)` / `readback --input <proposal.json>`: it follows the installed history graph and verifies every prior source, not a predicted union of old IDs.

## Retrieval and actual effect

Build the archive-aware index from the installed masters. The default `master_index.py query` returns bounded unique exact content. Follow `next_cursor` for text. For provenance use `query --index <index> --term <same-term> --origins <group_id>` (preserve the original `--controls` setting) and follow that mode's independent cursor. Reassemble `text` per `group_id`/`character_offset`; reassemble `origin_json` by its character offset and parse it only when `origins_complete` is true. The origin document retains every source/role, occurrence and ancestor edge. `--page-chars` budgets the complete compact ASCII wire response including LF; callers that pretty-print must budget their own formatter. Legacy Python callers can retain `query`; `--legacy-output` exposes that explicit CLI shape. Never equate near wording with identity or hide contradictory claims. Missing/stale sources and incomplete pages remain explicit.

Use the repaired path in the next necessary current query/update. Compare the same query and source cut for transmitted bytes, duplicate text, retrieved content/origins and elapsed cost; retain unavailable metrics. Current-view reduction is not evidence of shorter product delivery. Reorganize the affected family again when a real change makes it stale; do not rescan every unrelated task, impose a quota, or rely on another user's reminder.
