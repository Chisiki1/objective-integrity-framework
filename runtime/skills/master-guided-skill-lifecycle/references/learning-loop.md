# Learning loop: next use, not record count

Use at a material result, meaningful reuse, recurring failure, avoidable cost or decision-sensitive capability change. Ordinary read-only questions stay proportionate. The workflow and exact current source govern; this reference cannot grant permissions or impose a new deliverable.

## Consume existing knowledge efficiently

Read both current controls and search all applicable history. `scripts/master_index.py build --master <global> --master <project> --cache <explicit-inactive-cache>` follows exact `master-history-v1` markers and creates complete source/heading/occurrence coverage without editing masters. Reuse the same index at the same source cut. `query --index <index> --term <term> [--controls] [--cursor <cursor>]` searches reachable history as well as current text; controls select live roots, not obsolete archived controls. Follow pages before claiming complete query coverage. Plain `rg` on a compact master alone is not complete history search: use this route or read every exact linked backing. Missing/stale/cyclic backing holds only dependent retrieval; an empty query is not semantic inapplicability.

The ordinary query displays each exact section body once; its group ID leads to separately paged origins. Finish the required body and origin pages before making their respective completeness claims. Exact-byte display grouping is not semantic merging. Use `--legacy-output` only for a consumer that needs the former per-occurrence shape; the Python `query` API remains compatible. Budget the complete rendered response, including metadata, not just excerpt length.

At a decision-bearing organization trigger, use [master-reconciliation.md](master-reconciliation.md). Reconcile the whole affected current-control and knowledge scope, not just the latest event. `scripts/master_reconcile.py` validates explicit section dispositions and produces a lossless proposal; the old `master_index.propose_organization` remains for strictly historical subsets. Independent review, backing-first parent CAS, actual reachability readback and rollback remain required. An index build alone is not organization. Keep one source of current task state: reference its existing objective/work state rather than copying volatile phases, next actions, permissions or Skill versions. Preserve frozen cuts, pending outcomes and original evidence; a routing pointer grants no authority and must be read at use. Never remove unread authority or unknown effects by date, size or status guessing.

Keep current control scoped by owner/task and supersession. Do not replace another task's product control with the learning task. Semantic inventory reconciles touched families and preserves the full ID/disposition inventory and raw history; no model-selected summary may silently delete obligations. Similar wording, IDs or paths do not prove semantic equivalence.

## Make the next improvement action explicit

From the actual Project event, decide whether useful knowledge is confirmed, provisional, project-local, invalidated or superseded. Include success-based reusable methods and unnecessary procedures, not only failures. Prefer applying an existing invariant, revising/merging a Skill or removing a harmful mechanism over creating duplicates.

Use `scripts/learning_queue.py --help` for the installed exact command/schema. Its per-project explicit database stores candidate references and immutable transition history, not duplicate raw incidents. Bind owner, objective/source, Project event, sanitized Global disposition/link, causal family, artifact, next consumer/trigger, evidence and rollback appropriate to the stage. Use revision/CAS and idempotent event IDs; never overwrite an unknown effect with a retry. Missing metrics are unavailable, not zero. To correct stale reason/consumer/trigger references without lifecycle progress, use an explicit `change_kind: metadata` event with the same state, current revision and reason reference. Preserve identity, stage proof, previous source/evidence/rollback references and immutable history. Ordinary same-state transition remains invalid; do not fake promotion to repair the display.

The queue is a reminder and evidence-link validator, not action authority. A candidate is not improved operation. After recording, carry out its next eligible preparation, evaluation, independent challenge, bounded activation, actual use or effect assessment within current authority. Do not wait for a new user prompt once the existing source, no-drop, representative evaluation, independent challenge and recovery gates are closed. Preparing an inactive candidate may proceed while later activation evidence remains unproven; never demand a future successful effect before an authorized trial.

If present-task benefit does not recover the cost, retain a specific reason and next-use trigger. Revisit at that event, not on a timer. Retire a candidate only with an explicit disposition; preserve the underlying unresolved knowledge and all lineage. Measured harm can lead to narrowing, revision or rollback. Optional learning debt must not stall unrelated primary work.

## Verify application and effect

Retain the existing lifecycle effect/transition validators below this reference's entrypoint. Independently compare the actual changed action and consumer outcome to the predeclared baseline, including ordinary counterexamples, misses, recurrence, induced rework, false holds, elapsed/integration and maintenance cost. No single metric or local test implies general benefit. All-positive component evidence with no later real use still leaves learning effect unproven.

For a material change, update the existing Skill and registry member hashes only after the reviewed candidate is frozen. Distinguish materialized, registered, discoverable, selected, read, applied and measured. Instruction-only effects need actual action/outcome and independent observation. New permissions, materially uncertain semantics or a changed trust definition require the user; normal bounded improvements already authorized do not.

Report only decision-bearing learning: what changed, where it was next used, what was observed, and what remains unknown. No Skill quota, duplicate packet, extra mandatory agent, daemon or Stop continuation.

When the impediment is an operating rule, follow [condition-stewardship.md](condition-stewardship.md). Manage the condition's source/authority/scope/lineage through the same candidate and evidence references. Do not start another queue or infer permission from queue status. User-specified conditions can be explicitly amended by their user within authority; agent-owned methods can improve under standing scope. Neither route silently discards the original objective or unresolved source.
