# Skill application chain v1

## Unified owner and executor extension (2026-09-05)

Execution now also requires envelope.action_id to select exactly one compiler action_bindings entry. That entry must be finalized and ready, with the same canonical full final_payload/hash and complete tool_schema/hash as the envelope. Compiler valid=true alone is insufficient: unavailable schema or not-finalized may be valid observations but are not executable readiness. Legacy receipts without this binding remain historical/readable and cannot authorize new execution. Raw process stdout/stderr are retained as base64 and hashes before replacement decoding for display; decode trouble never erases executed effects.

The unchanged bundle/envelope schema also accepts COORDINATED-WORK with nonempty task_id, lease_id, chat_id equal to task_id and exact 64-hex source_sha256. Legacy WORK remains readable. These fields bind identity structurally; they are not trusted user-source provenance or action authority. Independent auditors and unbound children remain non-execution lanes. A bounded child may return a candidate to its primary owner; that does not impersonate the owner lane.

In addition to run-powershell, `run-script --bundle <bundle>` executes one selected `action-script` Python binding using the current interpreter with `-B`, without a shell. Its finalized payload has script_path equal to the selected canonical path, arguments as an exact string array, and execute boolean. prepare validates current member-set, selected bytes, script and schema; run-script checks script identity again and returns argv/process evidence. Unsupported runtimes use their explicit normal-workflow route, not guessed execution. Before action bind a capture plan; actual effect comes after the action. Instruction-only effects use lifecycle v3 actual action/result and independent observation, not a fabricated execution receipt. Below, WORK-only wording describes legacy mode, not a prohibition on the unified owner.

The caller-authored final-action envelope is an input, never evidence. `skill_application_bridge.py` binds that envelope to the exact Fact Compiler receipt, resolver input, selection receipt, required-read receipt, selected script path/hash, typed schema result, preflight, execution, action result, and lifecycle effect.

Caller-authored `FULL`, issuer, event, or external-export labels are not action-eligibility evidence and are rejected unless a separately configured trusted exporter with externally bound identity and signature is available; no such exporter is currently proven. The bridge opens every resolver-selected non-UI file itself, verifies its selected path/hash, and emits full base64 bytes plus a hash-bound `BYTES_DELIVERED` receipt in the current invocation output. This proves bridge byte delivery only, not model comprehension, which remains `UNPROVEN`. `HASH_ONLY` is not full application evidence; `UNAVAILABLE` holds only the dependent action.

`prepare` returns `GO` only when objective/source, final payload, a `WORK` owner lane with task ID and lease ID, available schema, selection snapshot, bridge-generated byte delivery, script bindings, and a current complete candidate member-set manifest close. The envelope, prepare, execution, action-result, and effect records must carry the same candidate member-set and the same owner lane; the bridge recomputes the member-set from the bound manifest/current root and `run-powershell` independently rechecks the lane before any selected-script or target execution. `SUPERVISOR`, `AUDITOR`, subagent, missing, or mismatched lanes hold before execution. `run-powershell` takes execution intent only from the bound final payload and invokes only the selected PowerShell Skill script at its receipt-bound path/hash. `BLOCK`, `ERROR`, and `HOLD` require `executed=false` and no target execution result. `effect` accepts only outcome-consistent, lane-consistent receipts, rejects hollow actual deltas, then invokes the selected lifecycle script.

The bridge proves relationship, identity, typed-bound, and observed process-result properties only. It cannot prove semantic Skill applicability, model comprehension, authority, root cause, scenario completeness, consumer outcome, or empirical improvement. Missing evidence causes a dependent hold; no-skill work continues through the normal workflow.
